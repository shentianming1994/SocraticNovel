# MAINTAINER.md — DL_FromScratch 维护者手册

> 本文件供**维护系统的人**阅读，运行时教学**不读取**本文件。
> 介绍系统结构、设计取舍、以及如何修改/扩展。

---

## 这是什么

DL_FromScratch 是一套 **SocraticNovel** 沉浸式学习系统，用于学习《深度学习入门：基于 Python 的理论与实现》（斎藤康毅）。它把三样东西结合在一起：

1. **苏格拉底教学法**——只问不说，让学习者自己走到答案（P0–P5 阶段，五级支持梯度 S5–S1）
2. **轻小说叙事**——三位老师（租借女友角色），有完整的性格、暗线、关系弧度
3. **角色轮值**——Ch.1–3 瑠夏 / Ch.4–5+AppA 千鶴 / Ch.6–8 墨

教学适配的核心原则：**先跑起来看结果，后理解数学原理。**

## 目录结构与加载策略

系统按「分层加载」设计，控制启动 context ≤ ~55KB：

| 层级 | 文件 | 加载时机 |
|------|------|---------|
| **核心层（始终加载）** | system_core / story / story_progression/overview / learner_profile / progress | 每次启动 |
| **按需层（课前加载）** | review_queue / 当课角色 / 当课 ch{XX} story+KP / 教材章节 / wechat_group | 课前 |
| **延迟层（用到才读）** | session_log/archive / mistake_log / diary / wechat_unread / temp_math / curriculum / KP overview / system_reference / appendix / unit_tests | 触发时 |

完整启动顺序见 `copilot-instructions.md`。

### 规则嵌入策略

为减少启动加载量，操作规则被嵌入到 AI「反正会读」的文件头部：

| 规则 | 嵌入位置 |
|------|---------|
| 隐喻空间规范 | `characters/sumi.md` 头部 |
| 群聊交互规则 | `runtime/wechat_group.md` 头部 |
| 日记写法 | `runtime/diary.md` 头部 |
| 数学公式格式 | `runtime/temp_math.md` 头部 |
| 文件压缩规则 | `runtime/session_log.md` 头部 |
| 情感阶段指引 | `story_progression/overview.md` |

完整版规则备查于 `config/system_reference.md`。

## 如何修改

### 改教学内容 / 知识点
- 编辑 `config/knowledge_points/ch{XX}.md`（LO 清单）和 `config/curriculum.md`（章节映射）
- 教材路径在各 KP 文件头部，改教材时同步更新

### 改剧情 / 角色
- 角色性格：`characters/*.md`
- 单章剧情节点：`story_progression/ch{XX}_*.md`
- 全局情感阶段 / 轮值：`story_progression/overview.md`
- 暗线节奏：`story_progression/appendix.md`

### 改教学法 / 叙事规则
- 高频规则：`config/system_core.md`（注意硬上限 22KB，超了要拆到 reference）
- 低频/参考规则：`config/system_reference.md`

### 改文件命名
⚠️ 改动文件名时，必须同步更新 `copilot-instructions.md` 的文件树**和**所有引用该文件的地方（overview.md 的文件索引、各章交叉引用）。

## 运行时状态文件

`runtime/` 下的文件由 AI 在教学过程中读写，**初始为空或仅含模板**：

- `wechat_group.md` 的「群聊消息」区为空 = 首次启动检测信号 → 触发序章
- `progress.md` 决定下节课排班
- 课后更新流程（8 步）见 `system_core.md` 和 `system_reference.md`

如果想**重置系统到初始状态**：清空 `runtime/` 下各文件的记录区（保留头部规则）、把 `progress.md` 重置为「Ch.1 待开始」、确保 `wechat_group.md` 消息区为空。

## 设计取舍记录

- **三位老师按专题分组而非等距轮换**：因为深度学习的章节有强依赖性，瑠夏（工程）适合基础+前向，千鶴（数学）适合学习机制+反向传播，墨（直觉/视觉研究）适合 CNN+深度。轮值与角色专长深度绑定，不建议随意调整。
- **情感峰值放在 Ch.7（CNN）**：因为 Ch.7 是「你第一次从零写出能用的网络」，技术成就感最强，适合承载情感高潮（E4+E5）。
- **AppA 放在 Ch.5 和 Ch.6 之间**：Softmax-with-Loss 是反向传播的延续，也是中期→后期的过渡呼吸点，承载条件事件 E3。
- **超自然设定：无**。三位角色都是现实的，重量来自真实的人物困境而非超自然元素。
- **墨的「手机强反差」**：墨当面最沉默（便签先行、需鼓勇气），手机/群聊里却最活跃——话多、连发、大量 emoji，"主动"几乎都在文字里。设计意图：文字是异步、可删改、不用当面出声的通道，正好绕开她最难的一关；这道反差让"成为能开口的人"的弧线更立体（她不是不能连接，是当面连接难）。**落地要点**：(1) 群聊在任何一章都发生，故规则同时备份在 `system_core.md`§2/§3、`story.md` 群聊设定、`wechat_group.md` 头部（每课课前必读），不能只放 `sumi.md`（仅墨的课加载）；(2) emoji 红线的唯一例外＝墨的文字消息，叙述散文与当面教学对话仍严禁 emoji；(3) 与旧"墨群里罕见发言/一个 emoji 是大事件"绑定的情节已重构——ch03 改为**埋设反差**的节点、ch05a 单 emoji 改读作"反常克制"、ch07 E4 夜的重量改为"褪去 emoji 的认真"而非"第一次发言"、备考期改群名的勇气改读作"给共同空间命名的 claim"而非"少发言的人开口"。墨弧线的真里程碑是**当面发声 E5**，不是群聊活跃度。
