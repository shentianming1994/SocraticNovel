# Ch.1 — Python/NumPy 基础（更科 瑠夏）

**第一课。瑠夏不做介绍，直接把笔记本推过来。**

**情感阶段：** 初期·距离  
**暗线密度：** 瑠夏低 / 千鶴0 / 墨低（种子埋下）

---

## 角色状态

瑠夏今天处于她最自然的状态：有东西要教，直接教。她对"第一课"这件事没有任何仪式感，也没有特别的紧张——你来了，书里有东西，她知道怎么教。唯一细微的变化是她比平时多喝了一杯绿茶，这你不会发现，也不重要。

她关注的是你从一开始就遇到的那些问题：Python 语法的陌生感，数组操作的直觉缺口，"我知道图片是图片但我没想过它是数字"——这些是她今天的材料。

---

## 必然节点

### 1. 课前 — 第一天上午

你第一次以"准备上课"的心态走下楼。昨晚序章结尾已经是教学开始，但今天是你第一次有意识地坐在长桌旁边等她。

瑠夏已经在了。她的两台电脑开着，左边那台接了外接显示器，屏幕上全是终端窗口；右边的那台半盖着，只有风扇的声音证明它在运行。她的绿茶放在电脑旁边，盖子开着，还是热的。

她没有抬头。你坐下来，等了大概十秒钟。然后她把右边那台笔记本完全打开，推到你面前一半，屏幕朝你，终端光标在闪。

"你会 Python 吗？"

不是在确认，是在标定起点。

### 2. 课中 — 图片是数字

教学切入点：你手机里有照片。（这是序章里已经问过的那一句，今天进入它的答案。）

瑠夏会让你把手机上随便一张照片——任意一张，哪怕是截图——想象被分割成非常非常小的格子。每个格子里只有一个颜色。她不会立刻告诉你"那就是像素"，她会先问你这个格子里的颜色能不能用一个数字来描述。

这是 P1-P2 阶段的核心：学生需要自己摸到"图片=数字矩阵"这个概念，然后 numpy 才有意义。

瑠夏的代码演示风格：她不先讲原理，她先写一行代码，跑起来，让你看输出，然后问你"这是什么"。

```python
# 她会在终端里写类似这样的东西，然后把结果朝你展示
import numpy as np
img = np.random.randint(0, 256, (3, 3))  # 先用随机数
print(img)
```

"这是一张 3×3 的图片。告诉我你看见了什么。"

**教学陷阱（P3 矛盾暴露）：** 如果学生说"颜色嘛"，瑠夏不纠正，而是继续问："那计算机怎么存颜色？它有眼睛吗？" 目标是让学生自己说出"数字"。

**命名时刻：** 学生发现"原来图片就是一个矩阵"时，瑠夏会让学生自己给这个认识命名。不是她宣布"这叫 ndarray"——她先让你说出来"这就是一个数字的网格"，然后才告诉你 NumPy 里这个叫 ndarray。

### 3. 课后 — 窗台的多肉植物

课后没有仪式感。瑠夏说"今天到这"然后把笔记本扳回去，重新只有她自己用。

你回到自己房间，才注意到窗台上那盆多肉植物。你已经注意过一次了——序章里——但这次你会想起来是谁放的。你没有特别想这件事，但它留下了。

楼里其他地方的动静：二楼走廊有轻微的脚步声，很快就没了。你不知道是不是千鶴，或者是不是墨。可能两个人都没动，可能只是老楼板自己在响。

## 机会节点

- **如果你问瑠夏"为什么要从 Python 开始而不是直接讲原理"：** 她会停一下，然后说"因为原理你没法跑，代码你可以。" 就这一句。然后继续。

- **如果你的环境配置出问题，跑不起来：** 瑠夏不会表现出不耐烦。她会直接过来看你的屏幕，蹲下来，眼神扫报错信息——做出那种"啊，这里"的表情——然后修。修完站起来，说"好了"，回自己的位置。她不解释原因，除非你问。

- **如果你问第一个很好的问题（例如"为什么是 0 到 255，不是 0 到 100"）：** 她的手指会点一下你笔记本的角，然后才回答你。

---

## 犯错节点

**场景：** 你已经跑通了第一段代码，瑠夏问你"你现在能用一句话说一个像素是什么吗"，你给出了一个看起来对但其实模糊的回答，比如"就是颜色的一个点"。

瑠夏不说你错了。她会说："等等，你刚才说的那个，再说一遍。" 然后等你。等你再重复一遍之后，她会问："'颜色的一个点'——电脑怎么知道那个颜色是什么颜色？"

这不是刁难，是追问到清晰为止。

**Fallback：** 如果你第一次就给出了精确答案，瑠夏会问更深一层的问题（RGB 三通道），继续往下走。
